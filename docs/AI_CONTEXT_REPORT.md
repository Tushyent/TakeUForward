# TakeUForward - Comprehensive Project Context & PRD

**Project Name:** TakeUForward
**Target Audience:** Engineering Students (18-24), Alumni, and Club Administrators (Primary focus: SSN College of Engineering)
**Current Status:** All Phase 1, Phase 2, and Phase 3 features (30+ total features) are fully implemented, audited, and deployed.

This document serves as a complete A-to-Z context guide, Project Requirements Document (PRD), and technical reference for AI assistants (ChatGPT, Claude, Gemini) or new developers joining the project.

---

## 1. Problem Statement & Vision (STAR Context)

**Situation:** Campus information (academic notes, placement guidance, event announcements, and peer mentorship) is historically fragmented across WhatsApp groups, scattered Instagram DMs, Google Drive links, and word-of-mouth. Crucial senior/alumni knowledge is lost the moment they graduate.
**Task:** Build a unified platform to centralize academic and placement knowledge, enable structured mentorship, and provide a safe space for honest questions without relying on who you know.
**Action:** Developed a 3-phase, custom-built MERN application encompassing strict domain auth, real-time chat, AI summarization, and an anonymity engine, scaling to support sub-communities and campus utilities.
**Result:** Successfully consolidated 30+ features (Notes, Chat, Referrals, Interviews, Lost/Found, Marketplace) into a highly optimized, deployment-ready product that enforces safety while connecting 4 distinct user roles.

## 2. Technology Stack & Architectural Metrics

The project uses a custom-built MERN-like stack without heavy frameworks like Next.js, explicitly chosen for robust foundation building.

*   **Frontend:** React.js + Vite (JavaScript), React Router for SPA routing, Axios for API calls.
*   **Styling:** Vanilla CSS (`index.css`) with a global design system of CSS variables (tokens for colors, typography, spacing). No Tailwind. Shared UI components built in `client/src/components/ui`.
*   **Backend:** Node.js + Express.js.
*   **Database:** MongoDB Atlas via Mongoose ODM. Features advanced aggregation pipelines (e.g., using `$addToSet` and `$pull` for race-condition-free upvotes, and `$unwind` for analytics).
*   **Authentication:** Passport.js (Google OAuth 2.0) with express-session (backed by `connect-mongo`).
*   **File Storage:** AWS S3. Uses **Presigned URLs** directly from the frontend to avoid bottlenecking the Node backend (Supabase Storage is the fallback).
*   **Notifications:** Nodemailer (SMTP) for emails + `web-push` API for browser push notifications (via Service Workers).
*   **AI Integration:** Google Gemini API (`@google/generative-ai`) for automated summarization of uploaded PDFs.
*   **Deployment Topology:** Vercel (Frontend), Render (Backend API), MongoDB Atlas.

## 3. Core Features (A to Z) & Numerical Rules

### 3.1. Authentication & Roles
*   **Domain-Restricted OAuth:** Students can only sign in using their official SSN college Google workspace accounts (`@ssn.edu.in`).
*   **Alumni Whitelist:** Alumni log in with personal Gmail accounts, but *only* if they have been pre-approved via a cryptographic invite link generated by admins/verified alumni.
*   **Role System:** 4 Roles: `student` (tagged by year/dept), `alumni` (verified badge, tagged by company), `club_admin` (can post to official club feeds), `platform_admin`.

### 3.2. Community & Mentorship (The Core Feed)
*   **Sub-Communities:** Reddit-style communities (e.g., `CSE-2028`, `Placements`, `General`).
*   **Discussion & Q&A:** Threaded posts and comments with upvotes. Filterable by tags (dept, year, course code).
*   **Trending (Hot) Sort Algorithm:** Sorts posts by engagement velocity using the formula: `(upvotes + comments) / max(1, hours_since_creation)`.
*   **Strict Anonymity Engine:** Users can post/comment anonymously. **Crucial Rule:** The `authorId` is physically stripped at the backend service layer before serialization. Anonymity is never just "hidden by CSS". Anonymous 1:1 DMs are disabled for safety.
*   **1:1 Direct Messaging:** Private identified chat between users. MVP uses **Polling** (fetching every 3-5s). Architecture is designed for a seamless upgrade to **WebSockets** (Socket.io) in the future without changing the data model.
*   **@Mentions & Notifications:** Real-time in-app dropdown + email + web push notifications alert the mentioned user.
*   **Weekly Digest:** A CRON job emails users a personalized weekly summary of top posts.

### 3.3. Academic Tools
*   **Resource Repository:** Students upload notes/PYQs. The backend passes file bytes to the Gemini AI API to generate a structured `aiSummary`.
*   **Course & Professor Reviews:** Rate and review electives/professors. Computes dynamic aggregates (avg rating/total reviews).
*   **Elective/NPTEL Aggregator:** Crowdsourced recommendations for electives.

### 3.4. Career & Placement Engine
*   **Alumni Directory:** Searchable verified alumni database, filtered by company.
*   **Referral Request Board:** Juniors post a target company; alumni match and connect via 1:1 chat. Uses an explicit 3-state workflow (`open`, `matched`, `closed`).
*   **Interview Experiences:** Structured repository of past interview rounds, difficulty, and outcomes.
*   **Mock Interview Pairing:** Match with alumni for specific company prep.
*   **Career Roadmaps:** Step-by-step guides (SDE, PM, Core) published by verified alumni.

### 3.5. Campus Utilities
*   **Campus Clubs:** Admin-managed pages for college clubs to post to a global "Announcements" feed without relying on Instagram.
*   **Teammate Finder:** Peer-to-peer team formation for hackathons.
*   **Lost & Found:** Board utilizing 1:1 chat for item coordination.
*   **Secondhand Marketplace:** Buy/sell/exchange books and electronics locally.

### 3.6. Moderation, Safety & Hard Limits
*   **Report Queue & Auto-Hide Threshold:** Any post, comment, review, or roadmap receiving **3 or more reports** is automatically hidden from the feed until manually resolved by a platform admin.
*   **Global Rate Limiting:** `apiLimiter` protects the API at **500 requests / 15 minutes**.
*   **Action Rate Limiting:** Destructive actions (e.g., `postCreationLimiter`, `applyTeamLimiter`) are capped strictly at **10 requests / 10 minutes** to prevent spam.

## 4. UI/UX & Design System

The application was completely overhauled in Phase 3 to function as a premium consumer product (akin to Discord or Notion) rather than a generic admin panel.
*   **Tokens:** Driven by CSS variables in `index.css` (e.g., `--primary`, `--bg-surface`, `--text-secondary`).
*   **Shared Components:** Reusable React components (`Button`, `Card`, `Badge`, `EmptyState`, `Spinner`, `Input`) located in `client/src/components/ui/`.
*   **3-State Rendering:** All API-driven pages strictly implement a 3-state render architecture: `Loading` -> `Error (with Retry action)` -> `Success (Empty vs. Populated)`.
*   **Layouts:** Pages utilize standardized wrappers (`.page-col-feed` for 720px timelines, `.page-col-wide` for 900px grids).

## 5. Security Architecture

1.  **Strict CORS & Cookies:** Cross-origin cookies are secured using `sameSite: 'none'` and `secure: true` (with Express `trust proxy: 1` enabled) to allow Render to safely attach sessions to the Vercel frontend.
2.  **No Leaked Secrets:** Environment variables (`.env`) are strictly guarded. AWS keys, JWT secrets, and MongoDB URIs are injected at runtime.
3.  **Sanitization:** Regex escaping is applied to all search queries globally to prevent NoSQL injection/ReDoS. Inputs are `.trim()`'d to prevent whitespace bypasses.
4.  **Error Flattening:** Global error middleware catches all exceptions (`next(err)`), preventing stack traces from leaking and averting fatal React rendering crashes (by flattening Object errors to strings).

## 6. How to Use This Context

If you are an AI assistant assisting a developer on this codebase:
1.  **Respect the Stack:** Do not suggest Tailwind CSS, Next.js, TypeScript, or Prisma unless explicitly requested. Adhere to vanilla CSS tokens, React Router, and Mongoose.
2.  **Maintain Anonymity:** Any new feature handling user-generated content must explicitly consider the `isAnonymous` flag and drop the `authorId` server-side.
3.  **Follow the Design:** Use the existing `client/src/components/ui/` components. Never use inline styles for fundamental layouts or colors.
4.  **Backend Rules:** Always wrap Express routes in `try/catch` and pass errors to `next(err)`. Never use `res.status(500).send()`.
